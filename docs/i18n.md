# Multilingua (i18n)

Il testo sorgente e' sempre l'**italiano**. La chiave del catalogo e' la stringa italiana stessa.

## Come funziona
- `src/i18n/core.ts`: `t('Hai {0} impegni', n)` (testo con segnaposto) e `translateText(testo gia' composto)` (corrispondenza esatta, poi per modello con `{0}`).
- `src/i18n/languages.ts`: le 12 lingue (it, en, es, fr, de, pt, zh, hi, ar, ru, ja, id).
- `src/i18n/apply.ts`: attiva la lingua e l'RTL (arabo). `src/i18n/catalogs.ts` registra i cataloghi.
- `src/i18n/locales/<lang>.json`: `{ "testo italiano": "traduzione" }`. Le parti variabili usano `{0}`, `{1}`... nello stesso ordine in tutte le lingue (l'insieme dei segnaposto deve coincidere).
- `src/components/T.tsx`: `Text` e `TextInput` che traducono da soli (importarli da `@/components/T`).
- Fuori dai componenti (toast, Alert, testi composti in logica) usare `t(...)` dentro funzioni/componenti, mai a livello di modulo.

## Elenco delle stringhe: `src/i18n/source.json`
Generato da `node scripts/extract-i18n.mjs` (AST con `@babel/parser`, nessuna dipendenza nuova). Scrive anche `src/i18n/source.meta.json` (`count`, `byFile`, `withPlaceholders`).

Criteri di estrazione (in `src/**/*.ts(x)`, esclusi `src/i18n/locales`, `tests`, `node_modules`, `src/data/translations.json` e i dati demo `seed.ts`, `marketSeed.ts`, `jobsSeed.ts`, `moodDemo.ts`, `network-seed.json`, `src/store/demo.ts`):
- testo JSX (`JSXText`) con lettere, spazi collassati;
- attributi JSX di testo: `title label placeholder accessibilityLabel accessibilityHint text subtitle hint description header empty caption sub desc detail tagline cta name message body heading emptyText confirmLabel cancelLabel` (letterali, template, condizionali);
- espressioni `{...}` figlie di elementi JSX con stringhe / template / condizionali / `&&`;
- primo argomento di `toast()`, `showUndoToast()`, `t()`; titolo, messaggio e bottoni di `Alert.alert()`; `message`/`title` di `Share.share()`;
- proprieta' di oggetti con chiavi di testo (`title text label name desc description detail hint tagline placeholder msg message body sub subtitle cta why summary sentence tip action explanation reason heading note question answer ...`);
- in piu', qualsiasi altro letterale "italiano-like" che non sia chiaramente logica (confronti `===`, `case`, import, tipi, chiavi di oggetto, argomenti di `includes/startsWith/split/test/...`, `console.*`, `go()`).
- "italiano-like": contiene lettere e (spazio, oppure accentate italiane, oppure iniziale maiuscola con >= 3 caratteri); scartati identificatori, camelCase, percorsi, URL, colori, `lp2-`, codice (`=>`, `;`, `{`), SOLO_MAIUSCOLE, nomi di file.
- Template con espressioni: `${x}` diventa `{0}`, `{1}`... in ordine; i rami di condizionali dentro il template (`${n === 1 ? 'impegno' : 'impegni'}`) sono estratti anche come voci separate.
- Normalizzazione: trim, spazi collassati, deduplica, ordine alfabetico. `EXTRA` e `NOISE` in cima allo script correggono a mano casi noti.

## Aggiungere una stringa
1. Scrivere il testo italiano nel componente (dentro `<Text>/Btn/Pill/Body` si traduce da solo) oppure usare `t('Testo {0}', valore)` fuori dai componenti.
2. `node scripts/extract-i18n.mjs` per rigenerare `source.json`.
3. `npm run i18n:translate` traduce in automatico le chiavi mancanti in tutte le lingue (vedi sotto). In CI lo fa il workflow `.github/workflows/i18n.yml` ad ogni push. Non serve tradurre a mano.
4. `node scripts/check-i18n.mjs` (o `npm run i18n:check`) per verificare.

## Aggiungere una lingua
1. Aggiungere il codice in `src/i18n/languages.ts` (nome nativo, direzione RTL se serve).
2. Creare `src/i18n/locales/<lang>.json` (anche `{}`) e registrarlo in `src/i18n/catalogs.ts`.
3. Aggiungere il codice alla lista `LANGS` in `scripts/check-i18n.mjs`, `tests/i18nCatalog.test.mjs`, `scripts/i18n/catalog.mjs` (+ `LANG_NAMES`), `src/i18n/catalogs.ts` (anche `src/i18n/overrides/<lang>.json` con `{}`), le mappe per lingua in `i18n/glossary.json` (`style`, `terms.*.tr`) e `scripts/i18n/pricing.json`; poi `npm run i18n:translate -- --lang=<lang>`.

## Traduzione automatica (build / CI)

Le traduzioni non si scrivono a mano: un comando trova le chiavi mancanti e le fa tradurre da un motore, con protezioni e controlli qualita'. **Le traduzioni automatiche non sono riviste da madrelingua**: vedi "Correggere una voce" piu' sotto.

### Setup (una volta)
Scegli un motore e imposta la chiave (mai nel repo): variabile d'ambiente oppure file `.env.local` nella radice (ignorato da git, formato `NOME=valore`).

| Provider | Variabili | Note |
|---|---|---|
| `anthropic` (consigliato) | `ANTHROPIC_API_KEY`, opz. `ANTHROPIC_MODEL` (default `claude-haiku-4-5`) | Claude via API; segue glossario, registro e istruzioni sui comandi; tutte le 11 lingue. |
| `deepl` | `DEEPL_API_KEY` (chiavi `:fx` = api-free), opz. `DEEPL_GLOSSARY_<LANG>`, `DEEPL_EXTRA_LANGS` | Copre en es fr de pt zh ar ru ja id. **Non l'hindi** (hi): serve un fallback (`--provider=deepl,anthropic`). Verifica l'elenco aggiornato con `GET /v2/languages?type=target`. Formalita' dal glossario. |
| `google` | `GOOGLE_TRANSLATE_API_KEY` | Cloud Translation v2 (Basic), tutte le lingue. |
| `libretranslate` | `LIBRETRANSLATE_URL`, opz. `LIBRETRANSLATE_KEY`, `LIBRETRANSLATE_ZH_CODE` | Gratuito e auto-ospitabile, qualita' inferiore: le voci con token rovinati vengono scartate (riportate come fallite). |
| `mock` | - | `[lang] testo`, per provare la pipeline senza rete. |
| `none` | - | Solo report. |

Senza `--provider` si usa il primo con chiave disponibile (ordine: anthropic, deepl, google, libretranslate). `--provider=deepl,anthropic` crea una catena: per ogni lingua vale il primo provider che la supporta. Senza nessuna chiave il comando si ferma con "Imposta ANTHROPIC_API_KEY o DEEPL_API_KEY ...".

### Comandi
```
npm run i18n:extract            # rigenera src/i18n/source.json
npm run i18n:translate:dry      # cosa manca + stima costo, nessuna chiamata
npm run i18n:translate          # traduce le chiavi mancanti (chiede conferma col costo stimato)
npm run i18n:translate -- --yes --lang=de,ja --max=200
npm run i18n:check              # CI: exit 1 se mancano chiavi o ci sono valori non validi
npm run i18n:prune              # rimuove dai cataloghi le chiavi non piu' nel sorgente
```
Opzioni di `node scripts/translate-i18n.mjs`: `--lang=xx,yy` `--provider=...` `--dry-run` `--yes` `--max=N` (per lingua) `--prune` `--retranslate=regex` (rifa' le chiavi che corrispondono; `all` = tutte) `--check` `--extract` `--strict` (gli avvisi QC diventano fallimenti) `--sort` (riordina come il sorgente) `--model=` `--batch=N` `--concurrency=N` `--max-cost=USD` `--source= --locales-dir= --overrides-dir= --glossary= --report=` (cartelle alternative, usate dai test).

Comportamento:
- Traduce solo le chiavi mancanti, quelle con valore vuoto/segnaposto diversi e quelle indicate da `--retranslate`; mai quelle che hanno un override.
- Dopo ogni lingua (e ogni ~5 s) scrive il catalogo in modo atomico, nello stesso formato di oggi (indent 0, UTF-8). Le chiavi nuove vanno in coda; i diff restano piccoli. Se interrotto (Ctrl+C, rete, quota) i progressi restano: rilanciando riprende da li'.
- Report finale (tradotte, copiate, fallite, avvisi) e file `.i18n-cache/report.json` (ignorato da git).
- Exit code 1 se ci sono voci fallite o lingue non coperte dal provider; 2 per errori di configurazione.

### Protezioni
Prima dell'invio il testo viene mascherato con token (`⟦0⟧` per i motori LLM, tag `<x>0</x>` / `<span class="notranslate">` per DeepL/Google/LibreTranslate) e ripristinato dopo, verificando che ogni token torni **una sola volta**. Sono protetti: segnaposto `{0}`, URL, email, numeri/orari, i nomi in `i18n/glossary.json` > `protected` (LifePilot, LifePoints, LifeNetwork, LifeClub, Theia, Apple Health, Google, Expo Go, IBAN, PDF, ...) e i **comandi per l'assistente** tra virgolette dritte negli esempi ("Dimmi ...", "Prova ...", elenchi che iniziano con una virgoletta): l'assistente capisce solo italiano e inglese, quindi il comando resta inglese in ogni lingua (si riusa la traduzione inglese gia' presente, oppure si traduce il comando in inglese col provider). Le chiavi che sono esse stesse comandi (`assistantCommandPatterns`) copiano la traduzione inglese; `keepVerbatim` elenca marchi e nomi di aziende copiati identici; regex e identificatori (`(?:...)`, `privacy:...`) si copiano.
Se la verifica dei token o un controllo QC fallisce, la voce viene riprovata una volta (batch piu' piccolo); se fallisce ancora **non viene scritta** e finisce nel report come "fallita". Non vengono mai scritti valori sbagliati.

### Controlli qualita' (`scripts/i18n/qc.mjs`)
Errori (la voce non si scrive): valore vuoto, insieme di segnaposto diverso, emoji assente nel sorgente, token residui, nota del traduttore, nessun carattere dello script atteso (zh/ja/hi/ar/ru) o script inatteso nelle lingue latine, comandi tra virgolette non rimasti in inglese. Avvisi (si scrive, si segnala): mescolanza di alfabeti, rapporto di lunghezza anomalo (>3x per i testi brevi, <0.2x; <0.1x per zh/ja), identica al sorgente, termine di glossario non rispettato (le lingue flesse possono variare: controllo per radice). Con `--strict` anche gli avvisi bloccano.

### Glossario (`i18n/glossary.json`)
`terms`: per ogni termine italiano (con regex `match`) la forma preferita per lingua (prima voce, inviata al motore come istruzione) e le forme accettate dal controllo (Impegno, Task, Colloquio, Bolletta, Fattura, Fornitore, Diretta, Umore, Salute, Finanze, ...). `style`: registro e formalita' per lingua (tu/du/vous... ru e ja formali). Il glossario nasce dalle traduzioni esistenti e dalle regole dei traduttori manuali; aggiungere un termine qui e rilanciare con `--retranslate=<regex>` per applicarlo. Per DeepL si puo' creare anche un glossario nativo e indicarlo in `DEEPL_GLOSSARY_DE=...`.

### Costi (stima da verificare)
Il comando stampa la stima prima di partire (`scripts/i18n/pricing.json`, tariffe indicative, da verificare sui listini). Ordine di grandezza per **rifare da zero** le ~6000 stringhe (~208k caratteri) in 11 lingue (~2,3 milioni di caratteri): Claude Haiku ~11 USD, Claude Sonnet ~34 USD, DeepL ~57 USD (500k caratteri/mese gratis sul piano Free), Google v2 ~46 USD (500k/mese gratis), LibreTranslate 0 (solo server). Nell'uso normale si traducono solo le chiavi nuove: poche decine di voci = pochi centesimi.

### CI (`.github/workflows/i18n.yml`)
Ad ogni push (e pull request): installa, `npm run i18n:extract`, esegue i test, verifica le chiavi mancanti. Se mancano e c'e' un secret, su push esegue `npm run i18n:translate -- --yes` e committa `src/i18n/locales/*.json`, `source.json` e `source.meta.json` con il bot (`chore(i18n): ... [skip ci]`; il workflow salta i commit del bot e quelli con `[skip ci]`, quindi niente loop). Senza secret emette solo un avviso e non blocca. Secret da creare in GitHub: Settings > Secrets and variables > Actions > New repository secret: `ANTHROPIC_API_KEY` (o `DEEPL_API_KEY`, `GOOGLE_TRANSLATE_API_KEY`, `LIBRETRANSLATE_URL`/`LIBRETRANSLATE_KEY`); opzionale la variabile (non secret) `ANTHROPIC_MODEL`. Le pull request da fork non vedono i secret: li' resta solo il controllo.

### Correggere una voce (override)
La qualita' di un motore non e' quella di un madrelingua. Per correggere una voce (o per fissarla definitivamente) aggiungi `"testo italiano": "traduzione corretta"` in `src/i18n/overrides/<lang>.json`. Gli override hanno **precedenza** sulle traduzioni automatiche (li applica `src/i18n/catalogs.ts` al caricamento, `check-i18n.mjs` li conta come tradotti), il runner non li legge per tradurre e **non li sovrascrive mai**, nemmeno con `--retranslate`. Per segnalare errori: apri una segnalazione con lingua, testo italiano e correzione proposta, oppure inviala direttamente come modifica all'override. Per rifare una voce automatica: `npm run i18n:translate -- --retranslate="^testo esatto$" --lang=de`.

## Traduzione a runtime: alternative

| Opzione | Pro | Contro | Uso |
|---|---|---|---|
| **A. Build/CI (implementata)** | Offline, zero latenza, nessun dato dell'utente verso terzi, controllata (glossario, QC, override), costo una tantum | Solo testi dell'app noti in anticipo | Tutta l'interfaccia |
| B. On-device offline (ML Kit Translate) | Funziona senza rete, privato, gratuito, adatto ai contenuti scritti dagli utenti | Richiede una development build (modulo nativo, non Expo Go), modelli da ~30 MB per lingua da scaricare, qualita' media | Post, commenti, chat in LifeNetwork/LifeClub |
| C. API cloud a runtime (DeepL/Google/Claude dal client o da un proprio server) | Qualita' alta, lingue illimitate | Costo ricorrente, latenza, dati utente verso terzi (consenso, informativa), chiavi mai nel client: serve un server | Solo con consenso e proxy server |
| D. Traduzione LLM on-demand lato server con cache condivisa | Una traduzione serve molti utenti, qualita' alta | Infrastruttura, moderazione, privacy | Contenuti pubblici di grande diffusione |

**Raccomandazione.** A per l'interfaccia (gia' attiva). Per i contenuti scritti dagli utenti (caso diverso: testi non noti in anticipo) B, con pulsante "Traduci" su ogni post/commento/messaggio: architettura proposta (non implementata):
1. Rilevamento lingua del testo (ML Kit Language ID) e confronto con la lingua dell'app; il pulsante compare solo se differiscono.
2. Opt-in esplicito nelle impostazioni (scarica i modelli solo su richiesta, Wi-Fi), nessun invio a server di terzi senza consenso; se in futuro si offrisse un motore cloud (C/D), sarebbe una scelta separata, esplicita e revocabile, con testo dell'informativa dedicato.
3. Cache locale (chiave: hash del testo + lingua di destinazione) con scadenza/limite di dimensioni; la traduzione resta etichettata "Tradotto automaticamente" con "Mostra originale".
4. Nessuna traduzione automatica di contenuti privati (chat cifrate) fuori dal dispositivo: solo on-device.
5. Richiede `@infinitered/react-native-mlkit-translate` o equivalente e una development build (`eas build --profile development`): verificare compatibilita' con SDK 57 prima di aggiungerlo (non e' stato installato).

## Controllare i cataloghi
- `node scripts/check-i18n.mjs [--min=NN] [--lang=en,es]` stampa per lingua copertura, chiavi mancanti (prime 20), chiavi non presenti nel sorgente, valori vuoti, segnaposto diversi e (per zh hi ar ru ja) valori identici al sorgente. Exit 1 se ci sono segnaposto diversi o valori vuoti; la copertura bassa e' solo un avviso, a meno di `--min=NN`.
- `node --experimental-strip-types --test tests/i18nCatalog.test.mjs`: nessun valore vuoto, segnaposto coerenti, chiavi presenti nel sorgente (la copertura non e' verificata; passa anche con `{}`).
- `node --experimental-strip-types --test tests/i18nTranslate.test.mjs`: test del runner con provider finto (maschere, QC, glossario, retry, CLI end-to-end su cartella temporanea).
- Gli override in `src/i18n/overrides/<lang>.json` sono uniti ai cataloghi da `check-i18n.mjs` e da `catalogs.ts`.
